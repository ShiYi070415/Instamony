## Instamony v1.3.5

HarmonyOS NEXT 原生客户端。本次更新集中在一件事上：**让私信里的分享卡片和「点开看」这条链路真的能用**，同时把首屏速度、后台通知、以及配套的自建中转工具补齐。

> 安装说明：`.app` 与 `.hap` 都是**调试证书签名**（可侧载），直接 `hdc install` 或应用市场外的安装器即可。换签名（发布证书）后必须卸载重装，登录状态会丢。

---

### 新增功能

**私信分享卡片（转发的帖子 / Reels）**
- 会话里转发的帖子、Reels、链接会画成卡片，不再是"一张封面图 + 一个灰块"。
- **帖子卡片**：宽 2/3 屏，顺序为 作者资讯栏 → 封面 → 正文（正文白色、用户名粗体、两行省略号）。
- **视频卡片**：宽为帖子卡片的 2/3，圆角封面铺满，作者栏**悬浮**在左上角（沉浸光感底、宽度跟随文本），正中一颗播放三角。
- 卡片上**点击**进应用内 **reels 类页面**（不再跳网页）：只带短码与本地算出的 pk 进页，封面 / 视频 / 作者 / 正文全部按 `media/{pk}/info` 现取，页面里能看正文、动作区（赞 / 评论 / 收藏 / 转发）可用。
- 供调试用的诊断行：`direct share kind=… user=… cap=… code=…`、`detail ready key=… video=… like=… comment=…`。

**会话页**
- 同一进程内再进同一条会话会先铺**内存快照**（`core/ThreadSnapshot`：按账号分区、最多 6 条会话、10 分钟），画面 0 毫秒就有，网络回来整份替换；不落盘，遵守"不要文本快照缓存"的约定。

**后台与通知**
- 退到后台会申请**短时任务**额度，并每 45 秒看一眼收件箱；未读变多就发本地通知（回到前台立刻交还额度）。
- 说明：HarmonyOS 的**离线推送（Push Kit）只对应用市场分发的正式包开放**，侧载包拿不到 push token，详见下面「已知问题」。

**诊断**
- 设定 → 诊断新增 **「复制中转材料（会话 + 推送 token）」**：一次把 IG 会话 Cookie 与设备推送 token（含取 token 的错误码）以 JSON 放剪贴板，供自建中转使用。

**配套工具（仓库内）**
- `tools/relay/relay.js`：BYO 中转，单文件零依赖，Windows / Linux / Android-Termux 通用；只读低频轮询收件箱（默认 90s、最低 60s、±15% 抖动），支持 `agc` / `meow` / `telegram` / `webhook`（企业微信、飞书、Bark 格式）四种通道。
- `tools/agc/agc.js`：AGC 自检（`--token` / `--app` / `--certs` / `--push` / `--sa-token`），用来判断"推送为什么没 token"。
- `tools/shots/mock-shots.ps1`：按真实排版生成 1080×1920 商店截图（合成数据，无隐私内容）。

**文档**
- `docs/privacy.html`：可直接托管到 GitHub Pages 的隐私政策页。
- `docs/store-listing.md`：AGC 的 Brief / Full introduction（中文已按 17 字上限调整）。

### UI

- 分享卡片：封面与文字同属一张卡（外层一次圆角 + 裁剪），材质底座改为透明以避免压暗光感；视频卡片圆角统一。
- 卡片文字：作者名、正文改白色，正文前拼粗体用户名；帖子卡片作者行放大（头像 26、名字 15）；视频卡片作者行放大（头像 20、名字 12）。
- 设置页：「复制中转材料」提到诊断分组第一项（之前排在第三项，不易发现）。

### 修复

- **分享卡片完全不显示**：正常打开会话走的是 `threadFromJson`，而它构造消息时漏传了全部 share 字段（只有实时补丁那条传了），导致卡片分支永远进不去。
- **reels 页显示应用图标而不是封面**：封面从未被回填，页面走到 `startIcon` 兜底；现在按 pk 取回后写入封面与真实宽高，且没有封面时不再画应用图标。
- **作者头像不显示**：`header_icon_url` 被误当成封面候选，头像字段因此一直为空。
- **会话封面没被包在卡片里**：上一版是"封面 + 另一块材质块"两段拼装，各自圆角，视觉上封面悬在卡外。
- **内嵌网页可加载任意地址**（安全）：内置网页握着用户的登录态 Cookie，却能导航到任意网址。现在限定 `instagram.com / cdninstagram.com / fbcdn.net / facebook.com`，**站外链接一律交给系统浏览器**；这也是 AGC"是否提供不受限的网络访问"一题能如实回答 No 的前提。
- 中转脚本被 PowerShell 写入 BOM 导致 `node relay.js` 报 `Invalid or unexpected token`。

### 性能

- **私信列表首屏**：预取从"等首屏有帖子 + 手停下（最多 12 秒）"改成开 app 后 600ms 就发；首屏那一发用 `interactive` 优先级；第一页请求收小到 15 条会话 × 5 条预览。冷启动实测出列表约 **1.5 秒**（同一发请求 883ms、TaskPool 解析 33ms）。
- **会话首屏**：请求提前到 `pushPath` 之前发出（与 300ms 滑入动画重叠）；同进程内再进直接铺内存快照。
- **分享卡片点开**：短码 → pk 改为**本地 64 进制解码**（省掉一次 oembed 往返），详情请求支持优先级并合并并发，卡片出现在会话里就开始预取，进页基本命中缓存。
- 详情请求加内存缓存（24 条）与在飞请求合并。

### 已知问题 / 待办

- **Push Kit 在侧载包上不可用**：`pushService.getToken()` 返回 `1000900010 Illegal application identity`（云端 `VerifyCloudCapability 1003400002`）。已验证：加指纹、换发布证书签名都解决不了 —— 发布签名**无法侧载安装**（`9568322 not trusted app source`），所以必须走 **AppGallery 内部测试 / 上架**才能拿到 token。中转脚本的 `agc` 通道已备好，等这一步。
- **离线通知目前依靠自建中转 + IM 机器人**（企业微信 / 飞书 / Telegram / MeoW），不是应用原生推送。
- AGC 上架材料：文案与 6 张截图已就绪；隐私政策页需替换两处占位（邮箱、仓库地址）后挂 GitHub Pages。
- 长时任务（常驻后台）未做：私信检查不属于任何 `backgroundModes` 类型，硬套既过不了审核也费电。
- 中转的 IG 侧风控：一台机器只建议挂一个账号、轮询不快于 60 秒（同一 IP 多账号会被判定成脚本农场）。
